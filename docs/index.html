ARCHITECTURE OVERVIEW

CivitForge is structured as a layered system. Each layer has a single responsibility and communicates through typed message passing. The entire stack is written in Rust with zero unsafe code in production paths.

Federation is achieved through the ActivityPub protocol layered on top of HTTP. Each instance maintains a local event log that is synchronized via a custom DAG merge protocol.

LAYER 01

TRANSPORT -- Federated Mesh

Peer discovery, encrypted channels, and replication coordination. Built on ActivityPub (ForgeFed) with custom HTTP signature verification and DAG-based merge.

activitypub forgefed webfinger http-sig
LAYER 02

STORAGE -- Content-Addressed Layer

All objects stored by their SHA-256 hash. Garbage collection is trivial: unreferenced hashes are unreferenced bytes. Supports pluggable backends: local FS, S3, and custom.

sha-256 cas-v2 merkle-trees pluggable-backend
LAYER 03

RUNTIME -- Rootless Execution

Pipeline runner using namespace isolation without privilege escalation. Builds execute as the invoking user identity with capability-based resource limits.

nsjail landlock seccomp oci-runtime
LAYER 04

AI -- Air-Gapped Intelligence

Local inference engine for code analysis. Models run in isolated sandboxes with no network egress. Results are cached and versioned alongside code.

vllm tree-sitter qdrant air-gap-enforced
// Quick start

GET STARTED

01

Install

Clone and build from source. No runtime dependencies beyond the Rust toolchain.

git clone https://github.com/WyattAu/CivitForge.git
cd CivitForge
cargo build --release
02

Configure

Initialize a new instance with default configuration.

civitforge init --name my-forge
civitforge config edit
03

Run

Start the forge server. Access the web UI at localhost:8080.

civitforge serve --port 8080
open http://localhost:8080
